## C. Code Understanding

### Question 21

**Identify the comment in the following code:**

```python
# Display a message
print("Hello")
```

**Answer:**
The comment is:

```python
# Display a message
```

It explains that the program will display a message.


### Question 23

**Which of the following names is easier to understand for storing a student's name?**

```text
x
student_name
a
```

**Explain your answer.**

**Answer:**
`student_name` is easier to understand because it clearly describes what information the variable stores. Names like `x` and `a` do not clearly explain their purpose.

### Question 24

**Identify which names are written in snake_case:**

```text
student_name
StudentName
total_marks
TOTAL_MARKS
```

**Answer:**
The names written in `snake_case` are:

```text
student_name
total_marks
```

Snake_case uses lowercase letters with words separated by underscores.

### Question 25

**Which of the following is a commonly used class naming style?**

```text
student_record
StudentRecord
STUDENT_RECORD
```

**Answer:**
`StudentRecord` is a commonly used class naming style in Python. This style is called **PascalCase**.

---

### Question 26

**Consider:**

```python
name = "Rahul"
Name = "Amit"
```

**Are `name` and `Name` treated as the same name in Python? Explain why.**

**Answer:**
No. `name` and `Name` are treated as different names because Python is **case-sensitive**. Lowercase and uppercase letters are considered different.

---

### Question 27

**What is wrong with using names such as `x`, `y`, and `z` everywhere in a large program? Is using short names always wrong?**

**Answer:**
Using names like `x`, `y`, and `z` everywhere can make a large program difficult to understand and maintain because their purpose is unclear. Short names are not always wrong. They can be useful for simple situations, such as loop counters.
